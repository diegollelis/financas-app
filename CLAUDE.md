# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Finanças App: a multi-user, public web app for monthly personal finance. Users record credits and debits, set a budget by percentages and track their balance. It replaces a personal Excel spreadsheet, which is kept out of the repo because it contains banking data. The repository is also a **full-stack learning lab** for the owner, who is moving from Protheus/AdvPL to modern web development. Explain the reasoning behind your choices, and record every new architectural decision as an ADR.

**Current state:** phases 1 (code foundation), 2 (auth and workspaces), 3 (financial core) and 4 (deploy) are done: the API has Better Auth with e-mail/password and Google (optional `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, ADR 0026) (`/api/auth/*`), a `SessionGuard` and `GET /me` (ADR 0020); the web app has sign-in (`/entrar`), sign-up (`/cadastro`) and sign-out, with route guards (ADR 0021); e-mail verification (required since ADR 0039: sign-up opens no session and shows "Confira seu e-mail", a repeated e-mail gets the same answer and its owner an e-mail, sign-in with an unverified e-mail answers 403 `EMAIL_NOT_VERIFIED` and sends a new link, a password reset verifies the e-mail, and the link returns to the `?voltar=` page) and password reset (`/esqueci-senha`, `/redefinir-senha`) are done (ADR 0022); auth routes are rate-limited per IP with counters in `rate_limits` (ADR 0023). Every user has a personal workspace (created on sign-up, ADR 0024); `GET/POST /workspaces` list and create workspaces; routes under `/workspaces/:workspaceId` go through `WorkspaceMemberGuard` (ADR 0025). OWNERs invite EDITORs/VIEWERs by e-mail; the link (`/convites/:token`) is accepted only by the invited e-mail (ADR 0027). Web pages: `/espacos/:workspaceId` (members, invitations) and `/convites/:token`. Phase 2 is done. Phase 3 (financial core) is done: the API connects as the `financas_app` role (no superuser, no BYPASSRLS) and `PrismaService.forWorkspace(id)` sets the RLS context (ADR 0028); `categories` is the first business table with the RLS policy: new workspaces get the default categories in the same transaction (`createDefaultCategories` + `setWorkspaceContext`), and `/workspaces/:workspaceId/categories` lists, creates, renames/archives and deletes them. The web page `/espacos/:workspaceId/categorias` manages them (delete is offered only for archived ones). The list also returns `recentUses` (transactions in the last 6 competências), which orders the "Mais usadas" group of `CategorySelect` (`features/categories/category-picker.tsx`: a search that ignores accents, a sheet of its own on the phone and a popover from md), used by every form that picks a category. `transactions` (lançamentos) has RLS too, a composite foreign key to `categories` (same workspace and type) and CHECKs on amount and period (ADR 0029); `/workspaces/:workspaceId/transactions?period=YYYY-MM` lists, creates, edits, settles (`PATCH { settledAt }`) and deletes. The web page `/espacos/:workspaceId/lancamentos?competencia=YYYY-MM` (default: this month in São Paulo) lists, creates, edits, settles in one click and deletes; status is derived on the client (`transactionStatus` in `packages/shared`). `budget_configs` (RLS) holds the budget of each competência someone saved; `GET /workspaces/:workspaceId/budget/:period` returns it or inherits the latest earlier one (`source: SAVED | INHERITED | DEFAULT`, ADR 0030), `PUT` saves it. The web page `/espacos/:workspaceId/orcamento?competencia=YYYY-MM` shows where the budget came from, previews each percentage in reais and lets EDITORs save it (VIEWERs get a read-only summary); saving invalidates every loaded competência, since later ones inherit. Percentages are typed with `parsePercent` and shown with `formatBasisPoints` (`packages/shared`). `GET /workspaces/:workspaceId/summary/:period` returns the month dashboard, computed by the pure `summarizePeriod` (`packages/shared`) in two views, planned and settled (ADR 0031); nothing is stored. The web page `/espacos/:workspaceId/painel?competencia=YYYY-MM` shows it (stat tiles, overdue notice, a stacked bar and a meter in HTML/CSS with the validated `--chart-1..3` colors, ADR 0032); transaction and budget mutations invalidate the `summary` query. The three competência pages share `PeriodNav` (previous and next, and the month itself opens a month-and-year picker with "Ir para o mês atual", `features/periods/period-picker.tsx`; only `?competencia=` changes, computed with `shiftPeriod`); what holds per-month state (forms, mutations) is keyed by the period. Phase 4 (deploy) is done: ADR 0033 records the free tier limits and the topology (a Cloudflare Pages Function proxies `/api/*` to Render, so web and API are the same site and the `Lax` cookie works). The proxy is written (`apps/web/functions/api/[[path]].ts`, logic and tests in `apps/web/edge/`), every API route is under `/api`, the API trusts the client IP only from the proxy, and `apps/api/Dockerfile` (built in CI) migrates on start (Render free has no pre-deploy). Production is live (runbook and URLs in `docs/deploy.md`; own domain `financas.codelelis.com`, DNS on Cloudflare, proxy kept, ADR 0039; with `VITE_CANONICAL_ORIGIN` set, the front redirects any other address to it before rendering, `apps/web/src/lib/canonical-origin.ts`): web + Function on Cloudflare Pages, API on Render, database on Neon; Google sign-in works in production (own OAuth client, consent screen published, privacy policy at `/privacidade`); Sentry reports errors from both sides in production (ADR 0034); the private repo `financas-backup` runs the encrypted backup daily, with a tested restore and a Sentry cron monitor (ADR 0035). Phase 5 started with the mobile-first front-end overhaul (ADR 0036), now done for every page: every `/espacos/:workspaceId/*` page renders inside `WorkspaceLayout` (header, bottom tab bar on the phone, sidebar from md), which loads the workspace once; pages read it with `useCurrentWorkspace()` and show their own query states with `QueryState`. "/" is not a page: it opens the last workspace used (`features/workspaces/last-workspace.ts`), and workspaces are switched and created in the header (`workspace-switcher.tsx`); the account menu (`features/shell/`) also picks the theme (Sistema/Claro/Escuro, `lib/theme.ts`, applied before the first paint by `public/theme-init.js`). `GET /workspaces/:workspaceId/analysis?from=&to=` (ADR 0037) returns planned and settled sums by competência, type and category for up to 24 months; the pure functions in `packages/shared/src/analysis.ts` shape them (monthly series, category ranking, category series) and apply the filters on the client; the page `/espacos/:workspaceId/analise` keeps its range and filters in the address (`features/analysis/filters.ts`) and draws the charts in its own SVG. Recurrences (ADR 0038): `/workspaces/:workspaceId/recurrences` lists, creates (with the first competência's transaction), changes and ends them; opening a competência (transactions list, summary, analysis) first creates the pending transaction of each active recurrence it lacks (`RecurrencesService.materialize`, one `recurrence_occurrences` row per recurrence and period, created in the same nested write; a deleted generated transaction is not generated again); changes and ends touch only pending transactions from this month on; a variable one (`variableAmount`) starts each month from the average of its last 3 settled and stays `amountEstimated` until its amount is given or it is settled, and the summary reports `estimatedCents`. Installment plans (ADR 0038): `/workspaces/:workspaceId/installments` lists (with `settledCount`), creates (all installments at once, total or per installment, `splitInstallments` puts the leftover cents on the last) and ends them; a transaction has `installment: { planId, number, count }`. The web page `/espacos/:workspaceId/recorrencias` (under "Mais") lists both, edits a recurrence sending only the fields that changed (each one sent is copied to the pending months) and ends either. Spreadsheet imports (ADR 0040): `/workspaces/:workspaceId/imports` lists, creates (up to 2,000 transactions in one nested write, all or nothing; categories checked at once with `ensureUsableCategories`; this route alone accepts a 4 MB body, the others keep 100 KB) and undoes them (deleting the import cascades to its transactions); the browser reads the .xlsx, the file never reaches the API. Only the template is read (`packages/shared/src/import-template.ts`: sheet "Lançamentos", columns found by title, `parseTemplateRows` gives rows plus an error/warning report per line; the category arrives as a name); `apps/web/src/features/import/workbook.ts` loads `read-excel-file`/`write-excel-file` on demand to read it and to build the template with the workspace categories. The web page `/espacos/:workspaceId/importar` (under "Mais") downloads the template, previews the rows by competência (check/uncheck, edit or fix a row in a sheet, match unknown categories; pure logic in `features/import/review.ts`), imports and undoes past imports. Terms of use (ADR 0041): the public page `/termos` carries `TERMS_VERSION` (`packages/shared/src/auth.ts`; changing it asks everyone to accept again); the e-mail sign-up requires `acceptTerms: true` and records the version (`users.terms_version`/`terms_accepted_at`, never from the body); `GET /me` returns `termsVersion`, and `RequireAuth` shows the acceptance screen (`features/auth/accept-terms.tsx`, `POST /me/terms`) instead of any page while it is not the one in force (accounts from before and Google sign-ups). Data export (ADR 0041): `GET /me/export` (`apps/api/src/account/`) sends a JSON attachment shaped by `dataExportSchema` (`packages/shared/src/data-export.ts`): the account, its logins and sessions, the owned workspaces in full and the others by name and role, never tokens or hashes; a test fails when a table with `workspace_id` is missing from `EXPORTED_TABLES`. The page `/conta` ("Minha conta" in the account menu) downloads it through `apiDownload` + `saveFile`. Tables: `imports`, `installment_plans`, `recurrences`, `recurrence_occurrences`, `budget_configs`, `transactions` and `categories` (RLS; `test/rls-coverage.e2e.spec.ts` requires RLS on every table with `workspace_id`), `workspaces`, `members`, `invitations`, `users`, `sessions`, `accounts`, `verifications`, `rate_limits`. Next steps are in `docs/roadmap.md`.

## Stack (see ADRs 0002–0028)

pnpm workspaces monorepo: `apps/web` (React 19 + Vite 8, TanStack Query, React Router 8, Tailwind 4 + shadcn/ui on Radix), `apps/api` (NestJS 12 as ESM on Express, Prisma 7, PostgreSQL 18), `packages/shared` (Zod schemas, types, money/date utils). TypeScript 6 (not 7: typescript-eslint does not support it yet). Auth is Better Auth with cookie sessions; email goes through Resend in production and Mailpit (Docker, inbox at http://localhost:8025) in development. Hosting: Cloudflare Pages (web), Render via Docker (api), Neon (Postgres). Locally, Postgres runs in Docker.

## Workflow

- `main` is protected: no direct pushes, no force pushes. Work on a branch, push it and open a pull request. Both CI checks (`Lint, typecheck, testes e build` and `Varredura de segredos`) must pass, and the branch must be up to date with `main`.
- GitHub CLI is not installed: after pushing a branch, give the user the `https://github.com/diegollelis/financas-app/pull/new/<branch>` link.
- The pre-commit hook runs gitleaks on staged files. Never bypass it (`LEFTHOOK=0`) to get a commit through; fix the finding.

## Gotchas

- **API is ESM:** relative imports in `apps/api` end in `.js` even in `.ts` files (`'./app.module.js'`).
- **`packages/shared` has no build** (ADR 0015): consumers import its `.ts` source. Inside it, relative imports end in `.ts`, and `enum`, `namespace` and parameter properties are forbidden (use `z.enum([...])`).
- **Prisma client is generated** into `apps/api/src/generated/` (git-ignored) on `pnpm install`. After changing `schema.prisma`, run `db:migrate` and then `db:generate`: with Prisma 7, `migrate dev` applies the migration but no longer regenerates the client. A business table needs its RLS policy written by hand: `db:migrate --create-only --name <change>`, append the policy to the generated SQL, then `db:migrate` and `db:generate`. `migrate dev` replays every migration on an empty shadow database, so hand-written SQL must not assume existing objects (e.g. `_prisma_migrations`). An index or unique key written by hand must also be declared in `schema.prisma` (same name), or `migrate dev` sees drift and waits for input. Migration folders are named with the **UTC** timestamp (`date -u +%Y%m%d%H%M%S`): a local-time name can sort before the migration it depends on. If `db:migrate` refuses to run non-interactively, write the SQL with `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script` (after `db:deploy`) into a new folder.
- **Shared versions** of `typescript`, `zod`, `prisma`, `@prisma/*` and `vitest` live in the `catalog:` of `pnpm-workspace.yaml`. Packages reference them as `"catalog:"`. Prisma is pinned exactly because npm's `latest` tag pointed at an 8.0 release candidate.
- **Install scripts** of dependencies are blocked by pnpm unless listed in `allowBuilds` (`pnpm-workspace.yaml`).
- **Env vars** are validated with Zod at startup (`apps/api/src/config/env.ts`, `apps/web/src/lib/env.ts`). Adding a variable means updating the schema and the `.env.example`. Tests never read `.env`; they get values from each `vitest.config.ts` (the API ones from `apps/api/test/test-env.ts`).
- **shadcn/ui** components are copied into `apps/web/src/components/ui/`. Run `pnpm format` after adding one.

- **API tests need Postgres** (ADR 0020): `pnpm test` migrates and uses a separate `financas_test` database, so run `pnpm db:up` first. CI has a Postgres service on the same port. HTTP tests call `resetDatabase()` in `beforeEach`; add new tables to its TRUNCATE.
- **Two database roles** (ADR 0028): the API uses `DATABASE_URL` (role `financas_app`: data only, no DDL, no TRUNCATE, subject to RLS); the Prisma CLI uses `MIGRATION_DATABASE_URL` (owner, read by `prisma.config.ts`). Tests do the same: `t.prisma` is the app role, while setup and cleanup use `ownerClient()`/`resetDatabase()` from `apps/api/test/db.ts`. Services read and write RLS tables through `this.prisma.forWorkspace(workspaceId)`; never open `$transaction` on that client, since each call is already one.
- **Web session and forms** (ADR 0021): the session is the TanStack query `['me']` (`useMe`); pages behind `RequireAuth` read the user with `useCurrentUser()`. Forms use React Hook Form + `zodResolver` with the shared schema. Page URLs are pt-BR. Page tests use `renderApp(path)` with `mockApi({...})`. After sign-in, `GuestOnly` goes to `?voltar=` (`features/auth/return-to.ts`, internal paths only). Errors from our own routes go through `apiErrorMessage` (`lib/error-message.ts`).
- **E-mail** (ADR 0022): inject `Mailer` (`apps/api/src/mail/`); templates are pt-BR with escaped HTML. Never log a message or its link (it carries a token). HTTP tests use `createTestApp()` (`apps/api/test/app.ts`), which swaps in a `FakeMailer`; open links with `mailer.lastLinkTo(email)`. Google sign-in tests fake Google's token endpoint with `fakeGoogle(profile)` (`apps/api/test/fake-google.ts`); `t.signUp(user)` returns a signed-in browser, the user id and the personal workspace id. Each `http()` client gets its own fake IP (`X-Client-IP` plus the proxy secret), so the auth rate limit (ADR 0023) only applies when a test pins one with `http({ ip })`.
- **Validating Nest routes** (ADR 0024): declare the shared schema on the parameter, `@Body({ schema: createWorkspaceInputSchema })`; the global pipe from `apps/api/src/common/validation.ts` answers 400 with `code: INVALID_INPUT` and the pt-BR message. `AuthModule` is global, so any module can use `@UseGuards(SessionGuard)`.
- **Every API route is under `/api`** (ADR 0033): Nest's global prefix, set in `setupApp`, plus Better Auth's `/api/auth`. Controllers and the route names in this file omit it; the web client and HTTP tests use the full path (`/api/workspaces/...`), and HTTP tests must call `setupApp` to get it.
- **Client IP** (ADRs 0023, 0033): Better Auth reads only `X-Client-IP`, kept by `trustProxiedClientIp` when `X-Proxy-Secret` matches `PROXY_SECRET` (required in production). Test `http()` clients send both; a request without the secret falls into one shared rate-limit counter.
- **Error reporting** (ADR 0034): Sentry starts in `apps/api/src/instrument.ts` (preloaded with `node --import` in the container) and `apps/web/src/lib/error-reporting.ts`, only when `SENTRY_DSN` / `VITE_SENTRY_DSN` is set. Data collection is off and `beforeSend` scrubs every event (`packages/shared/src/error-reporting.ts`); `AppExceptionFilter` redacts Prisma messages, which repeat query arguments, before logging or reporting. A new route that carries a token in its URL must be added to `TOKEN_SEGMENTS`. Never enable tracing, Session Replay or other SDK integrations without revisiting ADR 0034.
- **Better Auth** is mounted on Express before the body parser by `setupApp` (`apps/api/src/setup-app.ts`). The app is created with `bodyParser: false`, and HTTP tests must call `setupApp` too. Protect routes with `@UseGuards(SessionGuard)` and read the user with `@CurrentUser()`.

## Conventions that cut across the codebase

- **Multi-tenancy (ADRs 0008, 0025):** every business table has `workspace_id`. A workspace resource has `@Controller('workspaces/:workspaceId/<resource>')` + `@WorkspaceScoped()` (session 401 → member 404 → role 403), `@RequireRole('EDITOR')` on routes that change data, and reads the workspace with `@CurrentMembership()`. Services take that validated `workspaceId` and filter every query by it; never accept a workspace id from the body. Each new resource lists its routes in a test with `expectHiddenFromOutsiders` (`apps/api/test/isolation.ts`). Business tables also get the RLS policy of ADR 0028 (`NULLIF(current_setting('app.workspace_id', true), '')::uuid`); the local DB user is a superuser and bypasses RLS, so RLS needs the `financas_app` role (see `apps/api/test/rls-proof.e2e.spec.ts`).
- **Database (ADR 0017):** UUIDv7 ids; Prisma models in PascalCase mapped to snake_case plural tables; `created_at`/`updated_at` as `timestamptz(3)`.
- **Money and dates (ADR 0010):** use the helpers in `packages/shared/src/money-and-dates.ts` (`formatCents`, `parseReais`/`reaisInputSchema`, `todayIso`, `currentPeriod`, `formatIsoDate`, `formatPeriod`, `shiftPeriod`, `parsePercent`, `formatBasisPoints`); never `new Date("YYYY-MM-DD")` for display (time zone shift). Store amounts as integer cents (`amount_cents`, always positive; the sign comes from `CREDIT`/`DEBIT`). Store percentages as integer basis points. Use `period` (`YYYY-MM`) for the accounting month, `due_date`, and `settled_at` (null = pending). Never use floats for money.
- **Language (ADR 0011):** code, identifiers, DB, API routes and commit messages are in English (Conventional Commits). UI text and all docs are in pt-BR.
- **Validation (ADR 0006):** Zod schemas in `packages/shared` are the single source of truth. The API always validates (Nest's built-in `StandardSchemaValidationPipe`); the web client validates every response (`apps/web/src/lib/api.ts`). OpenAPI schemas come from `z.toJSONSchema`.
- **Tests (ADR 0013):** Vitest everywhere. Specs sit next to the code (`*.spec.ts`); API HTTP tests live in `apps/api/test/`. Web tests use `renderWithProviders` and query by visible text.
- **Privacy (ADR 0012):** never log request bodies, descriptions, amounts or tokens. Never commit `.env`, spreadsheets or DB dumps. `.sql` is deliberately _not_ ignored, because Prisma migrations are `.sql`.
- **Public repository (ADR 0019):** the GitHub repo is public, so the whole history is visible. Never put real credentials or real personal/financial data in code, tests, docs or commit messages; test data is always fictitious. A gitleaks pre-commit hook (lefthook) and a CI job enforce this. If a secret ever leaks, rotate it; rewriting history is not enough.

## Environment notes

Development is on Windows. Node 26 is installed, and it no longer ships corepack, so install pnpm with `npm i -g pnpm`. Docker Desktop, git and gitleaks are installed; Docker Desktop is not always running, so start it before `pnpm db:up`. Commits use the GitHub noreply e-mail (repo-local git config). Local ports: API 3333, web 5173, Postgres 5434 and Mailpit 8025 on 127.0.0.1 (3000/3001 and 5432/5433 are taken by other projects on this machine). When stopping dev servers, kill only `node` processes by port: a Windows `svchost` (port proxy) also listens on 3000.
