# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Finanças App: a multi-user, public web app for monthly personal finance. Users record credits and debits, set a budget by percentages and track their balance. It replaces a personal Excel spreadsheet, which is kept out of the repo because it contains banking data. The repository is also a **full-stack learning lab** for the owner, who is moving from Protheus/AdvPL to modern web development. Explain the reasoning behind your choices, and record every new architectural decision as an ADR.

**Current state:** phases 1 (code foundation), 2 (auth and workspaces), 3 (financial core) and 4 (deploy) are done: the API has Better Auth with e-mail/password and Google (optional `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, ADR 0026) (`/api/auth/*`), a `SessionGuard` and `GET /me` (ADR 0020); the web app has sign-in (`/entrar`), sign-up (`/cadastro`) and sign-out, with route guards (ADR 0021); e-mail verification (required since ADR 0039: sign-up opens no session and shows "Confira seu e-mail", a repeated e-mail gets the same answer and its owner an e-mail, sign-in with an unverified e-mail answers 403 `EMAIL_NOT_VERIFIED` and sends a new link, a password reset verifies the e-mail, and the link returns to the `?voltar=` page) and password reset (`/esqueci-senha`, `/redefinir-senha`) are done (ADR 0022); auth routes are rate-limited per IP with counters in `rate_limits` (ADR 0023). Every user has a personal workspace (created on sign-up, ADR 0024); `GET/POST /workspaces` list and create workspaces; routes under `/workspaces/:workspaceId` go through `WorkspaceMemberGuard` (ADR 0025). OWNERs invite EDITORs/VIEWERs by e-mail; the link (`/convites/:token`) is accepted only by the invited e-mail, and the OWNER sees the latest invitations with their status (pending, accepted, expired, and removed or left once the membership ends, recorded on the invitation by `removeMember`) (ADR 0027). `DELETE /workspaces/:workspaceId/members/:userId` lets the OWNER remove anyone else and any other member leave (the OWNER never leaves: `OWNER_STAYS`); `DELETE /workspaces/:workspaceId` (OWNER, never the personal one) deletes a shared workspace with everything in it by cascade (ADR 0041). Web pages: `/espacos/:workspaceId` (members, invitations) and `/convites/:token`. Phase 2 is done. Phase 3 (financial core) is done: the API connects as the `financas_app` role (no superuser, no BYPASSRLS) and `PrismaService.forWorkspace(id)` sets the RLS context (ADR 0028); `categories` is the first business table with the RLS policy: new workspaces get the default categories in the same transaction (`createDefaultCategories` + `setWorkspaceContext`), and `/workspaces/:workspaceId/categories` lists, creates, renames/archives and deletes them. The list also returns `recentUses` (transactions in the last 6 competências), which orders the "Mais usadas" group of `CategorySelect` (`features/categories/category-picker.tsx`: a search that ignores accents, a sheet of its own on the phone and a popover from md), used by every form that picks a category. In the transaction and recurrence forms it also offers "Adicionar 'Nome'" (`allowAdd`): the field then holds `newCategoryValue(name)` (`features/categories/new-category.ts`), and `useResolveCategory` creates the category of that type on save, or reactivates an archived one of the same name (ignoring case and accents). `transactions` (lançamentos) has RLS too, a composite foreign key to `categories` (same workspace and type) and CHECKs on amount and period (ADR 0029); `/workspaces/:workspaceId/transactions?period=YYYY-MM` lists, creates, edits (the type of a share, a split one, a month of a recurrence or an installment never changes: 409 `TYPE_LOCKED`, ADR 0029 note; on the web, editing keeps "Saída | Entrada" with the other type disabled and the reason under it, `SegmentedControl` options take `disabled`), settles (`PATCH { settledAt }`) and deletes. Payment methods (ADR 0054): transactions, recurrences and installment plans take an optional `paymentMethod` from a fixed list (`paymentMethodSchema`: PIX, DEBIT_CARD, CREDIT_CARD, MEAL_VOUCHER, CASH, BOLETO, TRANSFER, AUTO_DEBIT; `paymentMethodLabels` and `paymentMethodFieldLabels`, "Meio de pagamento" / "Meio de recebimento", in `packages/shared/src/payment-method.ts`), copied to each generated month and each installment, never to the shares of a split; "Cartão de crédito" is no longer a default category and "Bônus", "Cuidados pessoais", "Presentes e doações" and "Pets" are (workspaces created before keep theirs, ADR 0024 notes); on the web, the transaction form (right after the due date, out of "Mais opções", ADR 0054 note) and the recurrence edit pick it with `PaymentMethodSelect` (`features/transactions/payment-method-select.tsx`: the list plus "Nenhum"; a new transaction sends it only when there is one, an edit always), and the row, the table (under the merchant) and the search show it. The page `/espacos/:workspaceId/estabelecimentos` (under "Mais") lists them with a search (by name or alias), adds, renames, archives and reactivates, and deletes only an archived one nothing uses; each card shows only how many aliases it has ("2 apelidos"), and "Apelidos" in its menu (`features/merchants/merchant-aliases.tsx`) lists, adds and removes them; `MerchantSelect` finds a merchant by an alias too, showing the alias under the name (`NameGroup` items take `aliases`). `plainTransactionInputSchema` (no person, no merchant, no split) is what imports and forms `.pick()` from: Zod refuses `.pick()` on the refined create schema. Terms of use (ADR 0041): the public page `/termos` carries `TERMS_VERSION` (`packages/shared/src/auth.ts`; changing it asks everyone to accept again); the e-mail sign-up requires `acceptTerms: true` and records the version (`users.terms_version`/`terms_accepted_at`, never from the body); `GET /me` returns `termsVersion`, and `RequireAuth` (and `GuestOnly`, "/" and the invitation) shows `BrandLoader`, the CL symbol breathing, while loading, and "Tentar de novo" when the session check fails; it shows the acceptance screen (`features/auth/accept-terms.tsx`, `POST /me/terms`) instead of any page while it is not the one in force (accounts from before and Google sign-ups). Data export (ADR 0041): `GET /me/export` (`apps/api/src/account/`) sends a JSON attachment shaped by `dataExportSchema` (`packages/shared/src/data-export.ts`): the account, its logins and sessions, the owned workspaces in full and the others by name and role, never tokens or hashes; a test fails when a table with `workspace_id` is missing from `EXPORTED_TABLES`. The page `/conta` ("Minha conta" in the account menu, shown by `AccountLayout` in the frame of the last workspace used, no section marked; ADR 0044 note) downloads it through `apiDownload` + `saveFile`. Managing the account (ADR 0049): "Alterar nome" (`/api/auth/update-user`, only the name passes), "Trocar e-mail" (`/api/auth/change-email`: the link goes to the new address, which changes only once it is opened, and the address in use gets a notice; `sendVerificationEmail` tells a change from a sign-up by comparing with the stored e-mail), "Trocar senha" (`/api/auth/change-password`, the server always signs the other devices out) or "Criar senha" (the reset link, which creates a password for an account made with Google), and "Aparelhos conectados" from `GET /me/security` (whether there is a password, and the sessions without token or IP), with "Sair dos outros aparelhos" (`/api/auth/revoke-other-sessions`). Account deletion (ADR 0041): `GET /me/deletion` lists the owned workspaces shared with someone, which block it (`AccountDeletionService`); Better Auth's `deleteUser` e-mails a link to the web page `/conta/excluir?token=` (behind `RequireAuth`), which asks once more and sends `POST /api/auth/delete-user { token }`; the check runs before sending (`hooks.before`, 409 `OWNS_SHARED_WORKSPACES`) and again in `beforeDelete`, which deletes the workspaces only the person was in, the pending invitations to their e-mail and marks their accepted invitations elsewhere as `LEFT`; then `/conta-excluida` (public). Budget destinations (ADR 0047): `/workspaces/:workspaceId/budget-destinations` lists, creates, renames/archives and deletes them; Despesas (`EXPENSES`) is fixed and created with the workspace, and each `SAVINGS` one (Reserva de emergência and Investimentos by default) owns a debit category of the same name, created, renamed, archived and deleted with it (`createDefaultDestinations`, a transaction with `setWorkspaceContext`); archiving one takes its share out of the budget from the current competência on (earlier ones unchanged, note in ADR 0047); the categories and destinations lists say whether each is `inUse` (transactions, recurrences or installment plans), and only unused ones offer "Excluir"; the categories routes refuse to change such a category (`CATEGORY_OF_DESTINATION`), and the categories list marks it with `destinationId` (the page shows "Meta" and no menu). ## Stack (see ADRs 0002–0028)

pnpm workspaces monorepo: `apps/web` (React 19 + Vite 8, TanStack Query, React Router 8, Tailwind 4 + shadcn/ui on Radix), `apps/api` (NestJS 12 as ESM on Express, Prisma 7, PostgreSQL 18), `packages/shared` (Zod schemas, types, money/date utils). TypeScript 6 (not 7: typescript-eslint does not support it yet). Auth is Better Auth with cookie sessions; email goes through Resend in production and Mailpit (Docker, inbox at http://localhost:8025) in development. Hosting: Cloudflare Pages (web), Render via Docker (api), Neon (Postgres). Locally, Postgres runs in Docker.

## Workflow

- `main` is protected: no direct pushes, no force pushes. Work on a branch, push it and open a pull request. Both CI checks (`Lint, typecheck, testes e build` and `Varredura de segredos`) must pass, and the branch must be up to date with `main`.
- GitHub CLI is not installed: after pushing a branch, give the user the `https://github.com/diegollelis/financas-app/pull/new/<branch>` link.
- Versions are annotated semver tags on `main` with a GitHub release (ADR 0050). When handing over a PR, say what it means for the version: after the merge and a check in production, suggest the tag (patch, minor or major, read from the user's side) or say that it waits for the next batch. Never tag a commit that is not on `main` and live.
- The pre-commit hook runs gitleaks on staged files. Never bypass it (`LEFTHOOK=0`) to get a commit through; fix the finding.

## Gotchas

- **API is ESM:** relative imports in `apps/api` end in `.js` even in `.ts` files (`'./app.module.js'`).
- **`packages/shared` has no build** (ADR 0015): consumers import its `.ts` source. Inside it, relative imports end in `.ts`, and `enum`, `namespace` and parameter properties are forbidden (use `z.enum([...])`).
- **Prisma client is generated** into `apps/api/src/generated/` (git-ignored) on `pnpm install`. After changing `schema.prisma`, run `db:migrate` and then `db:generate`: with Prisma 7, `migrate dev` applies the migration but no longer regenerates the client. A business table needs its RLS policy written by hand: `db:migrate --create-only --name <change>`, append the policy to the generated SQL, then `db:migrate` and `db:generate`. `migrate dev` replays every migration on an empty shadow database, so hand-written SQL must not assume existing objects (e.g. `_prisma_migrations`). An index or unique key written by hand must also be declared in `schema.prisma` (same name), or `migrate dev` sees drift and waits for input. Migration folders are named with the **UTC** timestamp (`date -u +%Y%m%d%H%M%S`): a local-time name can sort before the migration it depends on. If `db:migrate` refuses to run non-interactively, write the SQL with `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script` (after `db:deploy`) into a new folder.
- **Shared versions** of `typescript`, `zod`, `prisma`, `@prisma/*` and `vitest` live in the `catalog:` of `pnpm-workspace.yaml`. Packages reference them as `"catalog:"`. Prisma is pinned exactly because npm's `latest` tag pointed at an 8.0 release candidate.
- **Install scripts** of dependencies are blocked by pnpm unless listed in `allowBuilds` (`pnpm-workspace.yaml`).
- **Env vars** are validated with Zod at startup (`apps/api/src/config/env.ts`, `apps/web/src/lib/env.ts`). Adding a variable means updating the schema and the `.env.example`. Tests never read `.env`; they get values from each `vitest.config.ts` (the API ones from `apps/api/test/test-env.ts`).
- **shadcn/ui** components are copied into `apps/web/src/components/ui/`. Run `pnpm format` after adding one.

- **API tests need Postgres** (ADR 0020): `pnpm test` migrates and uses a separate `financas_test` database, so run `pnpm db:up` first. CI has a Postgres service on the same port. HTTP tests call `resetDatabase()` in `beforeEach`; add new tables to its TRUNCATE.
- **Two database roles** (ADR 0028): the API uses `DATABASE_URL` (role `financas_app`: data only, no DDL, no TRUNCATE, subject to RLS); the Prisma CLI uses `MIGRATION_DATABASE_URL` (owner, read by `prisma.config.ts`). Tests do the same: `t.prisma` is the app role, while setup and cleanup use `ownerClient()`/`resetDatabase()` from `apps/api/test/db.ts`. Services read and write RLS tables through `this.prisma.forWorkspace(workspaceId)`; never open `$transaction` on that client, since each call is already one.
- **Web session and forms** (ADR 0021): the session is the TanStack query `['me']` (`useMe`); pages behind `RequireAuth` read the user with `useCurrentUser()`. A 401 from any of our routes (not `/api/auth/*`) means the session ended elsewhere: the `QueryClient` clears it (`features/auth/session.ts`) and `RequireAuth` sends to `/entrar` with a notice; `useMe` also rechecks on tab focus. Never handle 401 in a page. Forms use React Hook Form + `zodResolver` with the shared schema. Page URLs are pt-BR. Page tests use `renderApp(path)` with `mockApi({...})`. After sign-in, `GuestOnly` goes to `?voltar=` (`features/auth/return-to.ts`, internal paths only). Errors from our own routes go through `apiErrorMessage` (`lib/error-message.ts`).
- **E-mail** (ADR 0022): inject `Mailer` (`apps/api/src/mail/`); templates are pt-BR with escaped HTML. Never log a message or its link (it carries a token). HTTP tests use `createTestApp()` (`apps/api/test/app.ts`), which swaps in a `FakeMailer`; open links with `mailer.lastLinkTo(email)`. Google sign-in tests fake Google's token endpoint with `fakeGoogle(profile)` (`apps/api/test/fake-google.ts`); `t.signUp(user)` returns a signed-in browser, the user id and the personal workspace id. Each `http()` client gets its own fake IP (`X-Client-IP` plus the proxy secret), so the auth rate limit (ADR 0023) only applies when a test pins one with `http({ ip })`.
- **Validating Nest routes** (ADR 0024): declare the shared schema on the parameter, `@Body({ schema: createWorkspaceInputSchema })`; the global pipe from `apps/api/src/common/validation.ts` answers 400 with `code: INVALID_INPUT` and the pt-BR message. `AuthModule` is global, so any module can use `@UseGuards(SessionGuard)`.
- **Every API route is under `/api`** (ADR 0033): Nest's global prefix, set in `setupApp`, plus Better Auth's `/api/auth`. Controllers and the route names in this file omit it; the web client and HTTP tests use the full path (`/api/workspaces/...`), and HTTP tests must call `setupApp` to get it.
- **Client IP** (ADRs 0023, 0033): Better Auth reads only `X-Client-IP`, kept by `trustProxiedClientIp` when `X-Proxy-Secret` matches `PROXY_SECRET` (required in production). Test `http()` clients send both; a request without the secret falls into one shared rate-limit counter.
- **Error reporting** (ADR 0034): Sentry starts in `apps/api/src/instrument.ts` (preloaded with `node --import` in the container) and `apps/web/src/lib/error-reporting.ts`, only when `SENTRY_DSN` / `VITE_SENTRY_DSN` is set. Data collection is off and `beforeSend` scrubs every event (`packages/shared/src/error-reporting.ts`); `AppExceptionFilter` redacts Prisma messages, which repeat query arguments, before logging or reporting. A new route that carries a token in its URL must be added to `TOKEN_SEGMENTS`. Never enable tracing, Session Replay or other SDK integrations without revisiting ADR 0034.
- **Better Auth** is mounted on Express before the body parser by `setupApp` (`apps/api/src/setup-app.ts`). The app is created with `bodyParser: false`, and HTTP tests must call `setupApp` too. Protect routes with `@UseGuards(SessionGuard)` and read the user with `@CurrentUser()`.

## Conventions that cut across the codebase

- **Multi-tenancy (ADRs 0008, 0025):** every business table has `workspace_id`. A workspace resource has `@Controller('workspaces/:workspaceId/<resource>')` + `@WorkspaceScoped()` (session 401 → member 404 → role 403), `@RequireRole('EDITOR')` on routes that change data, and reads the workspace with `@CurrentMembership()`. Services take that validated `workspaceId` and filter every query by it; never accept a workspace id from the body. Each new resource lists its routes in a test with `expectHiddenFromOutsiders` (`apps/api/test/isolation.ts`). Business tables also get the RLS policy of ADR 0028 (`NULLIF(current_setting('app.workspace_id', true), '')::uuid`); the local DB user is a superuser and bypasses RLS, so RLS needs the `financas_app` role (see `apps/api/test/rls-proof.e2e.spec.ts`).
- **Database (ADR 0017):** UUIDv7 ids; Prisma models in PascalCase mapped to snake_case plural tables; `created_at`/`updated_at` as `timestamptz(3)`.
- **Money and dates (ADR 0010):** use the helpers in `packages/shared/src/money-and-dates.ts` (`formatCents`, `parseReais`/`reaisInputSchema`, `todayIso`, `currentPeriod`, `formatIsoDate`, `formatPeriod`, `shiftPeriod`, `parsePercent`, `formatBasisPoints`); never `new Date("YYYY-MM-DD")` for display (time zone shift). Store amounts as integer cents (`amount_cents`, always positive; the sign comes from `CREDIT`/`DEBIT`). Store percentages as integer basis points. Use `period` (`YYYY-MM`) for the accounting month, `due_date`, and `settled_at` (null = pending). Never use floats for money.
- **Language (ADR 0011):** code, identifiers, DB, API routes and commit messages are in English (Conventional Commits). UI text and all docs are in pt-BR.
- **Validation (ADR 0006):** Zod schemas in `packages/shared` are the single source of truth. The API always validates (Nest's built-in `StandardSchemaValidationPipe`); the web client validates every response (`apps/web/src/lib/api.ts`). OpenAPI schemas come from `z.toJSONSchema`.
- **Tests (ADR 0013):** Vitest everywhere. Specs sit next to the code (`*.spec.ts`); API HTTP tests live in `apps/api/test/`. Web tests use `renderWithProviders` and query by visible text.
- **Privacy (ADR 0012):** never log request bodies, descriptions, amounts or tokens. Never commit `.env`, spreadsheets or DB dumps. `.sql` is deliberately _not_ ignored, because Prisma migrations are `.sql`.
- **Public repository (ADR 0019):** the GitHub repo is public, so the whole history is visible. Never put real credentials or real personal/financial data in code, tests, docs or commit messages; test data is always fictitious. A gitleaks pre-commit hook (lefthook) and a CI job enforce this. If a secret ever leaks, rotate it; rewriting history is not enough.
